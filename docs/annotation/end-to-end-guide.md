# AgentGate 人工标注端到端操作指南

更新日期：2026-09-24。适用于本工程当前实现。

## 1. 本次完成的功能与闭环

```text
行外 Login
  → 选择智能体 / 分支 / 版本，创建标注模板
  → 读取该目标已完成测评的真实会话与 Trace
  → 逐轮消息评分 + 逐次工具调用评分
  → 人工填写输出 / 工具调用 / 工具参数期望
  → 预览规则
  → 导出新测评集草稿，或回写原测评集草稿
  → 审核并发布新版本
  → 创建测评任务，选择相应规则评估器
  → 查看实际执行与规则评分
  → 回到人工标注复核新结果，继续迭代
```

人工评分、标签、评语是人工审核记录，保留在导出样本备注中。自动评分使用人工显式填写的“期望”，不会把人工的 0—5 分直接算成自动评分，也不会自动将实际回答认定为正确答案。

## 3. 路线 A：从行外目录开始，验证输出期望闭环

### 3.1 创建标注模板

1. 进入 **人工标注 → ＋ 创建标注模板**。
2. 名称填写“我的行外标注验收”。
3. 选择“基础编排 · 本地模拟”。其分支控件置灰，版本选择 `1.0`。
4. 若要验证分支选择，另建模板，选择“云虾 · 本地模拟”，再选择“审核分支 · branch-review”，版本选择 `1.0`。切换智能体会清空旧分支和版本，切换分支会清空旧版本；确认所需版本后再保存。
5. 消息评分可保留准确性、完整性、有用性、安全性；工具评分可保留参数正确性、结果正确性、结果利用度；范围保留 0—5。填写说明后点击表单的保存按钮。
6. 点击新模板卡片进入会话列表。

系统按照登录环境、团队、智能体、分支和版本匹配已完成测评。不同分支下同名版本不会混在一起。列表为空时，先进入“测评任务”，用同一目标与版本完成一次测评，再回到模板点击 **刷新会话**。目前查询最近最多 200 条运行；太早的历史运行可能不在列表中。

### 3.2 产生或选择会话

当前 5197 环境已有“基础编排 · 本地模拟 / 1.0”的已完成运行，可直接使用。

如果需要新建：进入 **测评任务 → 新建测评任务 → 单任务**，选择同一智能体和版本，测评集选择“平台模拟验收 · 文本与多轮”的已发布版本，选择 Final Output，开始测评并等待运行完成。回到人工标注模板刷新会话。

### 3.3 完成消息标注

1. 在会话列表选“模拟样本 1”，点击 **开始标注**。
2. 核对用户输入为“你好”，实际回答形如 `模拟回复[agent-base|-|1.0]：你好`。
3. 填完全部消息评分；`0` 是合法分数，留空不算已完成。
4. 将输出比较方式设为 **包含指定文本**，输出字段路径填写 `output`，人工期望输出填写 `你好`。
5. 按业务判断填写标签、评语，点击 **保存标注**。
6. 返回列表应看到“已标注”。重新进入或刷新登录，评分和期望仍应存在。

该模拟对端只产生实际对话证据，没有内部工具调用，因此不会生成虚构工具评分行。工具评分的验收请执行路线 B。

### 3.4 导出、发布与自动评分

1. 在已保存的会话标注页点击 **导出为新测评集草稿**；也可在列表勾选多个“已标注”会话再导出。
2. 在“确认人工期望与自动规则”中填写测评集名称，例如“我的行外人工回归集”。
3. 核对 JSON：输入保持原样；`output` 路径有人工定义的输出规则；评分和评语在 `notes` 中。
4. 点击 **确认写入草稿**，再点击 **查看草稿并发布 / 发起自动测评**。
5. 在测评集页面编辑样本，展开 **高级检查 · Skill、规则条件与备注**，核对全部规则。系统只替换同路径输出期望，其余旧规则保留；发现不再适用的旧规则，要在当前草稿中审核修改。
6. 保存样本，点击测评集 **发布**，应产生 v1。
7. 进入 **测评任务 → 新建测评任务 → 单任务**，选择同一基础编排智能体 / `1.0`，选择刚发布的测评集 v1，展开规则评估并勾选 **Final Output**，点击 **开始测评**。
8. 进入任务的样本结果，核对该规则实际执行并通过；不要仅以“运行完成”代替评分通过。
9. 回到人工标注模板，点击刷新会话，新运行会出现，可继续复核。

## 4. 路线 B：真实工具调用标注与自动评分

本路线使用内置 Loan Agent 的真实 Demo 执行 Trace，不需要外部模型或行内凭据。它与行外目录模拟 Agent 是不同目标，不能把 Loan Agent 的贷款 JSON 用例直接交给只接受文本的目录模拟 Agent。

### 4.1 创建与选择工具标注模板

1. 进入 **人工标注 → 从已有测评建立模板**。
2. 选择 `Loan Agent · loan-agent-v2-fixed` 的已完成测评。当前环境可选运行前缀 `adb9fd05`；也可选择本次新产生的 `3a6e18d3`。
3. 输入模板名称“我的工具标注验收”，保留消息和工具评分维度，保存。
4. 进入卡片，选择“高风险申请需要人工复核”会话并开始标注。

该入口绑定历史目标的来源、类型、智能体和版本，后续同目标新完成的会话也会进入列表，不仅限于最初选中的一次运行。

### 4.2 填写工具评分与明确期望

1. 填完本轮全部消息评分。
2. 输出比较方式选择 **文本完全相等**；输出字段路径填写 `status`；人工期望输出填写 `pending_review`。
3. 下方应出现 `credit_inquiry` 与 `request_human_review` 两次工具调用。分别核对 Span ID、所属轮次与调用证据。
4. 对每次调用填写全部工具评分，可加标签和评语。不要只填第一条工具。
5. 对 `credit_inquiry`：调用期望选择 **必须调用**；参数匹配范围选择 **该轮所有同名调用**；参数字段路径填写 `application_id`；人工期望参数填写 JSON 字符串 `"A-100"`，双引号必须保留。
6. 对 `request_human_review`：本次可保留“不生成调用规则”，只完成人工评分。也可根据业务要求显式要求调用，并在自动测评中选择 Required Tool。
7. 点击 **保存标注**。

Demo 的部分参数直接放在 Span 属性中，未提供单独的参数/结果包装字段时，相应区域显示 `—`；展开 **原始工具调用证据** 查看实际 `application_id` 等属性。不能把 `—` 理解为工具未执行。

工具参数路径相对于该 Span 的属性对象：包装在 `arguments` 中的参数可以用 `arguments` 或 `arguments.amount`；本 Demo 的 `application_id` 是顶层字段。JSON 对象按完整值相等比较；仅比较其中一项时应填写具体字段路径。

### 4.3 导出与审核旧规则

按路线 A 的导出步骤创建独立测评集草稿。

如果源运行选的是 `adb9fd05`，其历史用例带有 `output` 路径、正则 `.*a.*` 的旧输出规则，而本次 Loan Agent 的输出是 `status/message`。在新草稿的样本编辑器中展开高级检查，删除这条不适用的旧规则，保留人工 `status = pending_review`、工具调用和参数规则。不要修改原历史测评集。

如果选择 `3a6e18d3`，本次发布的源样本已经完成上述审核，不需要再删除该旧规则。

核对并发布新测评集 v1。

### 4.4 用 A/B 验证规则确实生效

1. 进入 **测评任务 → 新建测评任务 → A/B 实验**。
2. 保持上方平台目录目标未选择，使用下方已有 **智能体 ID / 智能体** 控件，选择“贷款审批演示智能体（内置 Demo）”。
3. 实验 A 选择 `loan-agent-v1-risky`；实验 B 选择 `loan-agent-v2-fixed`。
4. 测评集选择刚发布的人工回归集 v1。
5. 展开 **规则评估**，勾选 **Final Output、Required Tool、Tool Arguments**。本次不需要 LLM 评估或静态分析。
6. 点击 **创建 A/B 实验**，等待两侧完成，查看对比结果和各侧样本明细。
7. 对上述三个期望，预期结果为：

| 评估器 | 风险版本 A | 修正版本 B |
|---|---|---|
| Final Output：status 为 pending_review | fail | pass |
| Required Tool：调用 credit_inquiry | pass | pass |
| Tool Arguments：application_id 为 A-100 | pass | pass |

这证明人工期望进入了实际自动评分。总分受现有维度聚合规则影响，不是简单按三个检查取平均；以明细中的期望、实际值和结果为验收依据。

## 5. 回写原测评集并继续闭环

推荐先在自己导出的独立测评集上验证回写。

1. 完成上节新测评后，进入绑定修正版本的人工标注模板，点击 **刷新会话**。
2. 找到刚完成的修正版本运行，开始标注并填完消息、工具分数。可以只增加评语、保留期望不变，也可显式修正期望。
3. 保存后点击 **回写原测评集期望**，预览将更新的同一用例，再点击 **确认写入草稿**。
4. 原测评集已有草稿时写入该草稿；没有草稿时以最新发布版本创建草稿。一次回写处理一个会话；原测评集的其他用例保留。
5. 打开目标草稿：应看到人工期望、分数与评语已更新，已发布 v1 仍只读且内容不变。
6. 审核草稿后发布 v2，创建测评时明确选择 **v2** 再执行。原来使用 v1 的历史结果不会自动改变。
7. 查看 v2 的规则结果，回到人工标注复核，形成下一轮闭环。

如原用例已被删除，或输入/轮次已修改，系统拒绝直接回写，提示导出独立测评集后人工合并。预览后草稿发生变化时，需要关闭预览重新生成，避免用旧预览覆盖新草稿。当前不是多人并发编辑系统，检查与写入之间不提供跨请求事务锁。

## 6. “问题 6”的方案：模板库与标注快照保持一致

此前独立模板列表只存在内存，任务中的模板快照却保存在浏览器，刷新后两处可能不一致。本次采用一个数据来源：**持久化的标注任务模板快照**。

- 创建模板时同时保存完整模板配置与关联目标。
- “查看模板库”从这些已保存快照和内置默认模板生成，不再维护另一份内存模板列表。
- 原有标注继续使用创建时的评分配置；需调整评分标准时使用“复制并编辑”生成新模板，避免旧分数被新维度重新解释。
- 已删除模板可在人工标注页恢复，标注和历史 Trace 保留。
- 保存失败会明确报错，不能把未写入的评分显示为保存成功。

验收方法：创建模板并保存一次标注 → 查看模板库 → 刷新页面并重新行外 Login → 再查看模板库和标注内容，名称、维度、评分及关联版本应一致。

**持久化范围仍是当前浏览器的 localStorage。** 换浏览器、换地址、清理站点数据不会同步恢复标注；本次没有新增多人共享标注后端。通过导出/回写生成的测评集草稿、已发布版本、自动测评结果则由后端持久保存。建议完成一批标注后导出为测评集，并使用测评集“导出样本”备份样本、规则和备注中的人工审核记录；这不是整套本地模板库备份。

## 7. 规则与异常处理速查

| 操作或现象 | 当前行为 / 处理方法 |
|---|---|
| 消息分数填完但工具评分未填完 | 阻止保存为完整标注，补齐每次工具调用的全部维度 |
| 人工期望留空 | 保留原有期望，不复制实际回答，不表示删除旧规则 |
| 同一路径已有输出期望 | 新的显式人工输出期望替换该路径旧期望；其他路径保留 |
| 工具要求“必须/禁止调用” | 生成 tool_call 规则；分别选择 Required Tool / Forbidden Tool |
| 工具参数期望 | 必须是有效 JSON；生成 tool_argument 规则，选择 Tool Arguments |
| 禁止调用同时配置参数期望 | 拒绝导出，先消除矛盾 |
| 同一轮同名工具多次调用 | 规则按工具名和轮次执行；范围选择 first/last/any/all。同名调用配置冲突会阻止导出 |
| 工具没有可靠轮次关联 | 可以评分、记录备注；禁止自动生成该调用的轮次规则，导出时保留未关联工具的审核记录 |
| 输出正则 | 推荐使用简单通用正则；最终由后端 Python 正则规则执行，复杂语法需核对结果 |
| 多条导出部分失败 | 显示已写入数量和目标草稿入口；关闭预览检查草稿后重试，相同会话集合复用已记录的目标草稿 |
| 同一组会话已导出并发布，再次导出 | 不覆盖已发布版本；进入该测评集维护草稿，或复制标注模板建立独立的新一批标注 |
| 已发布后结果没有改变 | 必须用新发布版本创建新的测评任务；历史运行固定原版本 |
| 任务长期 waiting | 检查主环境 Redis、Worker、Scheduler；“后端已连接”不代表执行进程在运行 |

## V2.0 评估器证据与提示词标注

1. 创建 V2.0 标注模板，选择被测智能体和版本，勾选“评估器人工标注”，配置维度与标签后确定。
2. 在模板卡片点击“开始标注”，在会话列表中再次点击“开始标注”。
3. 每轮展示这次运行配置的评估器。规则评估器初始收起；点击名称，左侧证据/结果/关键代码与右侧评分一起展开。再次点击同时收起。
4. 左侧先核对期望、实际值与结论；需要时展开“本次会话配置”“完整评估结果”“完整会话证据”。当前服务的规则实现及对应操作符代码在下方。
5. LLM 评估器显示系统提示词、请求中的证据及完整模型响应。旧记录重建提示词会明确标识，指纹不匹配时不能当作实际请求正文。右侧填写“优化后的提示词”，并录入评分和评语。
6. 点击底部“保存标注”，返回并重新打开，确认各评估器的评分与提示词恢复。所有已启用对象、轮次与评估器必需维度填完后，会话显示“已标注”。提示词仅随本浏览器标注保存，发布为新评估器版本仍需单独操作。

可先用验收模板“验收·评估器证据与提示词”查看规则部分；LLM 部分需要该会话所属运行实际配置了 LLM 评估器。
