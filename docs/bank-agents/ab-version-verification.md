## 页面验收

1. 行外 Login，打开测评任务，新建任务，选择 A/B 试验。
2. 在同一个贷款智能体下选择 `evolution-v1` 和 `evolution-v2`；原有 `v1` 仍可选。
3. 选择对应的“V1/V2 演进验收”测评集 v1。
4. 选择规则评估器、对应专项 LLM 或联合验收评估器，提交。
5. 在结果比较中查看指标差值和失败转通过；进入相同样本，核对两侧每轮路径、工具参数和最终状态。

### 保留的 V2 扣分及下一轮改进输入

- 基础编排第 05 例“无申请查询”：工具返回 no_application，回答同时说“审批结果：未通过”。LLM 单独评估记 0.80，联合实验的 LLM 子项记 0.49。应优先依据 status 区分“未申请”和“拒绝”，不能仅凭 approved=false 生成拒绝措辞。同类问题在两次独立执行中的扣分不同，应结合各自完整回答和证据人工复核轻重锚点；不能仅凭这个差值认定评估器不稳定。
- 基础编排联合实验第 03 例“阻断客户5万元仍拒绝”：状态与工具动作正确，但回答将高风险、低分和 blocked 并列，未明确阻断为决定原因，LLM 子项 0.79；此例 V1 通过、V2 未通过，是本次真实退化。下一轮应加强原因解释的优先级约束，并用相同样本重复验证，不能删除此记录。
- 本次没有修改测评期望、评估器或真实分数来消除上述问题，也没有在运行中替换智能体实现。回答质量剩余问题与执行链路故障分开记录。
