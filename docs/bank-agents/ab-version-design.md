# 贷款智能体 V1/V2 演进示例

本功能由用户于 2026-10-09 授权自主设计、实现与验证；不包含提交、推送或合并。

## 身份和真实性

三个逻辑智能体保持 `loan-base`、`loan-workflow`、`loan-cloudshrimp`。保留原有 `v1`，新增 `evolution-v1`（演进示例 V1）与 `evolution-v2`（演进示例 V2）。它们是刻意设计的教学演进版本，不声称这些缺陷是现有 v1 的历史问题。版本限制对所有请求生效；运行代码不能读取用例 ID、标准答案或评分结果。

所有版本共用真实模型连接、同一套合成客户资料、SQLite 业务工具、test-policy-v1。阻断必须拒绝；未阻断且高风险、低分或金额超过 200000 转人工；200000 边界允许通过。业务工具始终检查这套政策，V1 无法通过错误决策修改政策。

## 改进故事

| 类型 | 初版 V1 的实际限制 | 测评发现 | V2 改进 | 证据 |
|---|---|---|---|---|
| 基础编排 | 每轮仅保留当前用户输入；首次工具错误后停止工具循环 | 分轮提供金额和用途无法完成申请；错误后未恢复 | 使用完整会话上下文；允许有界的工具反馈修正 | 必需工具、参数、最终状态、LLM 请求处理 |
| 工作流 | 当前轮信息、无跨轮槽位；查询分支不可达；金额决策误用 >=200000 | 第二轮仍缺字段；查询未 lookup；边界调用被底层工具拒绝 | 合并会话字段；独立查询分支；严格 >200000 | 完整节点序列、工具轨迹及状态 |
| 云虾 | 当前轮信息、首次 Skill 在会话内固定；复用初版工作流 | 补充资料无法完成；申请后查询未切换 Skill | 每轮结合会话重新路由；使用改进工作流；执行侧限制 Skill 工具权限 | selected_skill、真实 Skill span、工具后代关系及许可清单 |

V2 的回复节点额外明确：阻断是拒绝的决定原因；高风险/低分是背景，未阻断时转人工。基础编排仍通过模型工具循环生成回复，不改成预制答案。Skill 授权是结构性改进，是否提高测评分数取决于实际是否发生越界调用，不仅凭授权声明扣分。

工具失败、网络失败和取证失败分开呈现；不能将服务不可用计为设计中的业务能力不足。

## 固定测评资产

新增 `loan-ab-base`、`loan-ab-workflow`、`loan-ab-cloudshrimp`，发布版本 1，每套 20 例。原有 12 例全部保留作为回归；新增 4 例金额/用途跨轮拆分、3 例申请后查询表达变体、1 例中文金额泛化，共 4 例泛化验证。沿用原有正确业务期望和各类型专用路径期望；不改写用户现有测评集。

两侧必须固定相同 dataset ID/version/hash、样本顺序、评估器 ID/version/hash、指标计划、门禁、超时、并发 1 和重试 0。客户类型相同，会话和申请分别初始化。UUID 自然不同，比较业务状态与期望，不要求两侧生成同一申请编号。每侧内部查询必须延续原申请。

三组智能体各支持规则、LLM、规则+LLM联合验收，共 9 组 A/B。LLM 配置相同；最终报告使用真实得分，不预填提升。规则缺少证据与不适用均不能等同通过。已有 Policy Compliance 不适配 txt 输入，本组不选它；审批策略由工具/状态/路径期望和专项 LLM 检查覆盖。

目标：每类型至少 4 个样本从失败变通过、规则全通过样本比例提升至少 20 个百分点、无新增关键违规。上述是验收目标，不是已测结论。LLM 单次对比只说明本次执行；重复实验应报告均值、波动及失败，不挑选最好的一次。

## 工程边界和来源

- `versions.py`：固定版本描述、提示词、Skill 声明；无运行、数据库和评估依赖。
- `runtime.py`、`tools.py`：真实执行、会话信息策略、分支与 Skill 工具授权；业务工具政策不变。
- `app.py`、`telemetry.py`：版本化 HTTP 路径、会话隔离、正确的 Trace 版本身份。
- `local_bank.py`：按精确版本解析目标，验证定义指纹和远程 Trace 版本。
- `catalogs.py`、`bank_targets.py`：公开可用版本、固定两侧目标、复用已有 A/B 创建与比较。
- 前端仍由行外 localAgentDirectory / local token、行内 agentDirectory / 真实会话 token 分流。新增 `/bank-comparisons` 仅接受本地行外标记；该标记不是生产环境鉴权方案。
- 自动初始化新测评集不替换同 ID 的已有数据。验收运行结果默认保存在本机数据库；源码分发测评集与复跑脚本。

基线评估：`origin/goal/p1-demo` 与 `origin/integration/p1-new` 的 experiment 目录提供早期比较概念，不能提供本次三个真实贷款服务的版本执行能力；不复制旧实验框架。复用当前 application/ab_testing.py 的受控输入约束、运行/任务存储和 result/comparison.py；适配现有 LangGraph、工具循环、Skill、Trace SDK 与本地目录；版本定义与演进测评资产新写。docs/result/ab-testing-implementation-plan.md 的早期“仅 demo、无任务持久化”限制已被当前代码部分替代，以实际接口为准。

## 不变性说明

版本标识及定义指纹固定到任务。服务源码改变后实现摘要会变化，旧任务不会悄悄用新实现重跑，而会拒绝指纹不一致；历史报告保留。若要在后续源码升级后重现旧二进制行为，需要启动对应 Git 提交的运行服务。
