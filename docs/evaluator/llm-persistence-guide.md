# LLM 评估器：保存、发布与按版本运行

更新日期：2026-10-08。

## 页面操作闭环

1. 进入 **评估器 → LLM 评估 → 新建 LLM 评估器**。
2. 填写名称、说明，选择后端已接入的评审模型。填写提供商和模型引用不会自动接入一个新服务；API Key 仍由服务端环境提供。
3. 配置评审输入范围、通过分数及各维度。每个维度填写名称、标识、说明、评分提示词和权重；权重必须为正数，合计 100%。默认提供相关性、正确性、简洁性、安全性、工具五个维度，可增删，至少保留一项，最多 64 项。
4. 点击 **保存**。成功后显示“草稿已保存到服务器”，草稿卡片会留在目录中。刷新页面并再次打开详情，应能恢复所有维度、模型、阈值和输入范围。
5. 点击 **发布并启用**。后端验证实现、配置及已注册模型提供商后，发布不可变 v1 并启用。仅保存草稿不能创建测评任务。发布验证不等于真实模型连接测试；模型可用性以实际运行结果为准。
6. 点击 **打开测评配置**，配置被测 Agent、测评集及执行设置，勾选此评估器。选择项显示发布版本。提交时发送明确的评估器 ID 和版本，任务保存完整配置快照。
7. 完成任务后，在 **任务详情 → 任务配置**（评估器配置区）查看当时的版本、模型、维度提示词、权重和阈值。在样本的 **评估结论与依据 → 原始评估记录** 中查看实际请求、响应、逐维度分数、置信度、理由及加权总分。
8. 回到评估器详情，点击 **创建新版本草稿**，修改提示词并保存。已有 v1 与历史任务保持不变；再次发布得到 v2。
9. 点击 **版本历史 → 查看 v1** 检查旧版本。历史版本只读；基于历史版本编辑仍进入独立草稿。已有草稿时优先打开该草稿，避免覆盖未发布内容。

部署本次代码后，API 和任务 Worker 都需加载新代码，才能共同识别新的维度评分执行版本。已有进程应按原部署方式重启；此文档不改变服务端模型连接、数据库和登录配置。

## 评分语义

页面中的发布版本 v1、v2 是某个评估器的内容版本；执行实现 `answer_quality@2` 表示多维度评分协议，两者不同。

- 新页面创建 `answer_quality@2`：一次模型请求携带所有维度提示词和按范围选取的实际执行证据。
- 模型必须为每个维度返回 `id`、`score`、`confidence`、`reason`、`review`。分数与置信度范围均为 0—1；不得缺失、重复或加入未知维度。
- 后端计算 `总分 = Σ(维度分数 × 权重 / 100)`，页面显示为 0—100 分。模型不决定加权总分。
- 任一维度要求人工复核，或置信度低于配置阈值，整体结果为待复核；否则按总分和通过阈值判定。
- 无最终输出时为不适用；超时、截断或非法响应不能视为通过。非法协议最多纠正一次，并保留请求、响应及纠正记录。
- 原 `answer_quality@1` 的整体评分协议与历史任务不变。复制旧整体评估器时，以一个整体维度承接原提示词及评分标准，用户可进一步拆分维度；发布后使用新的多维度协议。

## 持久化与引用

复用现有 Evaluator Catalog，没有增加浏览器持久化副本或另一套数据库：

| 操作 | HTTP 接口 | 结果 |
| --- | --- | --- |
| 首次保存 | `POST /api/evaluators` | 创建身份和服务端草稿 |
| 修改名称、说明 | `PATCH /api/evaluators/{id}` | 更新显示元数据 |
| 保存已有草稿 | `PUT /api/evaluators/{id}/drafts/current` | 替换草稿配置 |
| 重新进入页面 | `GET /api/evaluators/{id}` | 读取当前草稿和最新发布版本 |
| 创建新版本草稿 | `POST /api/evaluators/{id}/drafts` | 从明确的发布版本创建草稿 |
| 发布 | `POST /api/evaluators/{id}/drafts/publish` | 原子生成不可变版本，移除草稿 |
| 启用 | `PATCH /api/evaluators/{id}`，`enabled=true` | 允许新任务选用 |
| 版本历史 | `GET /api/evaluators/{id}/versions` | 读取已发布内容及指纹 |

普通任务、本地贷款、平台任务、平台 A/B 和稳定性任务贯通 `evaluator_refs`；原 A/B 路径沿用其既有精确版本字段。A/B 两侧固定同一组版本；预约和重跑沿用保存的运行快照。草稿、不存在的版本和停用评估器不能用于新任务。

行外目录使用 `localAgentDirectory`、合成 Token `local`；行内使用 `agentDirectory` 和真实会话 Token。本次没有改变该分流。

## 故障处理

- 保存失败：保留编辑内容，显示真实错误，不显示保存成功；修复连接后重试。
- 发布失败：保留草稿，显示后端校验错误，不会创建可用的假版本。
- 发布成功而启用失败：页面明确说明已发布版本，刷新后可点击“启用”。
- 保存期间禁用编辑、重复提交和关闭；离开未保存的修改需确认。

```sh
evaluator_test_dir="$(mktemp -d)"
AGENTGATE_DB="$evaluator_test_dir/tests.sqlite3" \
  AGENTGATE_LOG_PATH="$evaluator_test_dir/logs" \
  .venv/bin/python -m pytest -q
cd frontend
npm run check
npm run build
npx playwright test -c playwright.evaluator.config.ts
```

浏览器回归启动独立 FastAPI、临时 SQLite 与 Vite，验证真实 HTTP 保存、刷新恢复、发布和历史读取。测试模型指向不可调用的本机地址，浏览器测试不产生付费模型调用。执行评分由确定性 Judge 客户端测试，覆盖真实请求组装、加权、异常和运行快照。行内版本固定经过契约及浏览器模拟验证，本次未连接实际行内网关。
